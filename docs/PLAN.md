# خطة التنفيذ — النسخة الأولى

خطة بناء تطبيق ويب ثابت يقترح فطورا أو عشاء تونسيا، بدون خادم، في سبع خطوات قابلة للاختبار.

## النطاق

النسخة الأولى تجيب عن سؤال واحد: ماذا نطبخ الآن؟ كل ما لا يخدم هذا السؤال مؤجل.

| داخل النسخة الأولى | خارجها |
|---|---|
| أسئلة بالنقر: الوجبة، البروتين، طريقة الأكل، الوقت | طريقة التحضير والمقادير |
| ثلاث اقتراحات مع زر «غيرها» | قائمة المشتريات ومخزون الخضر |
| سجل ما طُبخ، محفوظ في الهاتف | المزامنة بين هاتفين والحسابات |
| عرض الطبخات، إضافة، تعديل، مفضلة، إخفاء | وضع رمضان |
| إعداد يوم السوق | الذكاء الاصطناعي |
| نسخ احتياطي: تصدير واستيراد ملف JSON | التثبيت كـ PWA والعمل بدون إنترنت (المرحلة 2) |
| النشر على استضافة مجانية | نسخة أندرويد في المتجر |

## التقنيات وبنية المشروع

موقع ثابت بـ Vite و React و TypeScript، بدون خادم وبدون مكتبات واجهة ثقيلة.

| الجانب | الاختيار |
|---|---|
| البناء | Vite + React + TypeScript (وضع strict) |
| التنسيق | CSS عادي بمتغيرات، تصميم للهاتف أولا (عرض 360px) |
| اللغة والاتجاه | `<html lang="ar" dir="rtl">`، نصوص الواجهة بالدارجة التونسية في ملف واحد |
| التخزين | localStorage بمفاتيح مرقمة النسخة (`dbara.v1.*`) |
| الاختبارات | Vitest لمنطق الاقتراح والتخزين |
| التنقل | حالة داخلية بسيطة أو hash routing، بدون مكتبة |
| النشر | GitHub Pages عبر GitHub Actions |

## أنواع البيانات

ثلاثة كيانات: الطبخة، سطر السجل، والإعدادات. أعمدة جدول الطبخات تتحول إلى هذه الحقول.

```ts
type Meal = 'ftour' | 'acha';              // فطور = منتصف النهار، عشاء
type Protein = 'meat' | 'chicken' | 'fish' | 'egg' | 'tuna';
type EatWith = 'spoon' | 'bread';
type Duration = 'quick' | 'normal' | 'long';
type Season = 'all' | 'winter' | 'summer';

interface Dish {
  id: string;                 // slug ثابت، مثلا "couscous-allouch"
  name: string;               // الاسم بالعربية
  meal: Meal | 'both';
  // AND بين المجموعات، OR داخل المجموعة.
  // "لحم أو دجاج" = [['meat','chicken']]
  // "بيض مع لحم أو دجاج" = [['egg'],['meat','chicken']]
  // "بدون" أو بروتين اختياري = []
  requires: Protein[][];
  eatWith: EatWith;
  family: string;             // كسكسي، مقرونة، مرقة...
  duration: Duration;
  season: Season;
  fresh: boolean;             // تحتاج حوتا أو خضرة من السوق
  description?: string;       // المكونات الأساسية، تظهر على البطاقة
  days?: (0|1|2|3|4|5|6)[];   // أيام مفضلة، مثلا كسكسي الجمعة (0 = الأحد)
  favorite?: boolean;
  hidden?: boolean;
  custom?: boolean;           // أضافها المستخدم
}

interface HistoryEntry {
  date: string;               // YYYY-MM-DD بالتوقيت المحلي
  meal: Meal;
  dishId: string;
}

interface Settings {
  marketDay: 0 | 1 | 2 | 3 | 4 | 5 | 6 | null;   // 0 = الأحد
}

interface AskInput {
  meal: Meal;
  available: Protein[];       // فارغة = بدون
  eatWith: EatWith | 'any';
  maxDuration: Duration;      // الافتراضي 'long' = لا قيد
}
```

مفاتيح التخزين: `dbara.v1.history` و `dbara.v1.dishes` (الطبخات المضافة وتعديلات المستخدم على الأولية) و `dbara.v1.settings`.

## خوارزمية الاقتراح

دالة صافية واحدة: `suggest(input, dishes, history, settings, now, rng)` ترجع قائمة مرتبة. الوقت والعشوائية يُمرَّران كمعاملات حتى تكون الاختبارات ثابتة.

### الإقصاء

تُحذف الطبخة إذا تحقق شرط واحد:

- مخفية.
- وجبتها لا تطابق الوجبة المطلوبة (و ليست `both`).
- إحدى مجموعات `requires` لا يوجد منها شيء في `available`.
- `eatWith` لا يطابق الاختيار (إلا إذا كان `any`).
- مدتها أطول من `maxDuration`.
- طُبخت في آخر 3 أيام.

### الأوزان

كل طبخة باقية تبدأ بـ 10 نقاط.

| القاعدة | النقاط |
|---|---|
| طُبخت منذ 4 إلى 7 أيام | −6 |
| طُبخت منذ 8 إلى 14 يوما | −2 |
| نفس عائلة طبخة اليوم أو البارحة | −5 |
| نفس عائلة طبخة منذ يومين | −2 |
| مفضلة | +3 |
| تستعمل بروتينا متوفرا | +1 |
| فصلها يطابق الفصل الحالي | +3 |
| فصلها عكس الفصل الحالي | −9 (قليلة الظهور وليست ممنوعة) |
| اليوم الحالي من أيامها المفضلة | +4 |
| نفس بروتين طبخة اليوم أو البارحة (البروتين المحدد فقط) | −2 |
| طازجة، ونحن في يوم السوق أو اليوم الذي بعده | +3 |
| طازجة، ومرّ 4 أيام أو أكثر على يوم السوق | −3 |
| عشوائية | من 0 إلى 2 |

البروتين المحدد هو الذي لا خيار فيه (مثل «لحم» وليس «لحم أو دجاج»).

الفصول: الشتاء من نوفمبر إلى مارس، الصيف من جوان إلى سبتمبر، وباقي الأشهر محايدة. إذا لم يُحدَّد يوم السوق لا تُطبَّق قاعدتا الطازج.

### العرض

- تُعرض أعلى ثلاث، و«غيرها» يعرض الثلاث التي بعدها.
- إذا كانت النتائج أقل من ثلاث: يُلغى قيد طريقة الأكل ثم قيد المدة، مع رسالة تقول أي قيد أُلغي.
- إذا لم تبق أي طبخة: رسالة واضحة مع زر للرجوع إلى الأسئلة.

الأوزان تقديرية وتُعدَّل بعد أسبوعين من الاستعمال، لذلك تُجمع في كائن ثوابت واحد في أعلى `suggest.ts`.

## الشاشات

خمس شاشات، وشريط تنقل سفلي بأربعة أزرار: اليوم، السجل، الطبخات، الإعدادات.

| الشاشة | المحتوى | التفاعل |
|---|---|---|
| الأسئلة (الرئيسية) | أربعة أسطر من الأزرار: الوجبة، البروتين، طريقة الأكل، الوقت | الوجبة تُختار تلقائيا: فطور قبل 15:00، عشاء بعدها. زر كبير «اقترح عليّ» |
| الاقتراحات | ثلاث بطاقات: الاسم، العائلة، المدة، المكونات، وسبب قصير («ما طيبتوهاش من جمعة») | «هذي» تسجل الطبخة وتنتقل للسجل. «غيرها» تعرض الثلاث التالية |
| السجل | آخر 30 يوما، سطر لكل وجبة | حذف سطر، إضافة طبخة يدويا بتاريخ ووجبة |
| الطبخات | القائمة مع بحث بالاسم | مفضلة، إخفاء، تعديل، إضافة طبخة جديدة بكل الحقول |
| الإعدادات | يوم السوق، تصدير واستيراد البيانات | قائمة أيام الأسبوع مع «ما عنديش». التصدير ينزّل ملف JSON |

قواعد الواجهة: أزرار بارتفاع 44px على الأقل، لا إدخال نصي في المسار اليومي، وآخر اختيارات البروتين وطريقة الأكل تُحفظ كقيم افتراضية للمرة القادمة.

## خطوات التنفيذ

سبع خطوات بالترتيب، كل واحدة تنتهي بـ commit وبشرط قبول يمكن التحقق منه.

1. **الهيكل.** إنشاء مشروع Vite + React + TypeScript، ضبط RTL والخط العربي، ESLint، Vitest، وشريط التنقل بشاشات فارغة.
   - القبول: `npm run dev` يعرض واجهة عربية من اليمين لليسار، و `npm test` و `npm run build` ينجحان.
2. **البيانات.** كتابة `types.ts`، وتحويل جدول `docs/dishes.md` إلى `src/data/dishes.json` مع `id` لكل طبخة.
   - القبول: اختبار يتحقق أن كل طبخة لها قيم مسموحة، وأن المعرّفات فريدة، وأن العدد يطابق الجدول.
3. **منطق الاقتراح.** كتابة `dates.ts` و `suggest.ts` حسب قسم الخوارزمية.
   - القبول: اختبار لكل قاعدة إقصاء ولكل وزن، واختبار لتخفيف القيود عند قلة النتائج، كلها بـ `now` و `rng` ثابتين.
4. **التخزين.** كتابة `store.ts`: قراءة وكتابة السجل والإعدادات وتعديلات الطبخات، مع دمج الطبخات الأولية وتعديلات المستخدم، والتصدير والاستيراد.
   - القبول: اختبارات للقراءة من تخزين فارغ، للدمج، ولاستيراد ملف غير صالح دون فقدان البيانات.
5. **المسار اليومي.** شاشتا الأسئلة والاقتراحات، مربوطتان بالمنطق والتخزين.
   - القبول: من فتح التطبيق إلى تسجيل طبخة في 4 نقرات على الأكثر، والطبخة المسجلة لا تُقترح في اليوم الموالي.
6. **الشاشات الثانوية.** السجل، الطبخات، الإعدادات.
   - القبول: إضافة طبخة جديدة تظهر في الاقتراحات، إخفاء طبخة يزيلها منها، وتغيير يوم السوق يغيّر ترتيب الطبخات الطازجة.
7. **النشر.** ملف `deploy.yml` لـ GitHub Pages، ضبط `base` في Vite، و README فيه أوامر التشغيل والنشر.
   - القبول: الرابط العمومي يعمل على هاتف أندرويد بعرض 360px، والبيانات تبقى بعد إغلاق المتصفح.

بعد الخطوة 7 يبدأ أسبوعا التجربة في الدار، ثم تُراجع الأوزان والقائمة قبل المرحلة 2.

## كيف تبدأ

1. أنشئ مستودعا على GitHub باسم `dbara`.
2. نفّذ خطوات التنفيذ بالترتيب، خطوة واحدة في كل مرة.
3. بعد كل خطوة: شغّل الاختبارات والبناء، تحقق من شرط القبول، اعمل commit.
4. لا تضف أي ميزة من عمود «خارجها» في قسم النطاق.

راجع قائمة الطبخات مع زوجتك قبل الخطوة 2، لأن تصحيح الجدول أسهل من تصحيح ملف JSON.
